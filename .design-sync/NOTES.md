- The design system lives at `frontend/src/design-system` (primitives + composites), embedded inside the `frontend` app — it is not a standalone package with its own `package.json`/`dist`.
- `frontend/src` must be treated as strictly read-only during sync. A prior sync run rewrote files under `frontend/src` and produced an unwanted 95K+ token diff. All build/bundle output must go to a separate build directory (e.g. `ds-bundle/` or a temp dir), never back into `frontend/src`.
- No Storybook in this repo (no `.storybook/`, no `*.stories.*` files) — shape is `package`.
- No standalone `package.json`/`dist` for the design system itself — it's synth-entry mode, built directly from `frontend/src/design-system/index.js` via `--entry`. `.d.ts` contracts are weaker than a real TS build since components are plain `.jsx` with no PropTypes/JSDoc.
- `PKG_DIR` resolves to `frontend/` (nearest ancestor `package.json`, walked up from the entry) — so `cssEntry` must live inside `frontend/`. The compiled Tailwind CSS is produced by `npm run build` (vite) into `frontend/dist/assets/index-<hash>.css`; since the hash changes every build, `buildCmd` copies it to a stable `frontend/dist/ds-styles.css` and `cssEntry` points there. `frontend/dist` is gitignored and gets wiped/regenerated by every build — never touches `frontend/src`.
- Fonts (Geist, Geist Mono) are loaded via a Google Fonts `<link>` tag in `frontend/index.html`, not shipped as local files or referenced via CSS `@import`. Classified as `runtimeFontPrefixes: ["Geist"]` (a runtime font service) rather than `extraFonts`, since there's no local font file or CSS `@import` to extract from the repo. This suppresses `[FONT_MISSING]` but previews will render with the fallback font unless the design agent's environment also loads Geist — flagged as a known limitation, not silently swept away.
- No components read React context/providers — plain prop-driven functions, so no `cfg.provider` needed.
- `cfg.extraEntries: ["react-router-dom"]` is required for `SetupDoneScreen`'s preview to render at all — without it, the preview's own `MemoryRouter` import and the bundled `SetupDoneScreen`'s internal `useNavigate()` resolve to two separate esbuild-bundled copies of react-router-dom with different React Context identities, so the Router context is invisible to the hook (`useNavigate() may be used only in the context of a <Router>`, even though a `<MemoryRouter>` visibly wraps it). Putting the package in `extraEntries` merges it into the single `_ds_bundle.js` IIFE so both resolve to the same module instance. Tradeoff: this triples the bundle size (172KB → 581KB) and adds ~130 router exports to `window.BookmarkDS` that no other component needs — accepted since `SetupDoneScreen` couldn't otherwise render at all, and the real app already ships react-router-dom.
- `SetupDoneScreen` calls `useNavigate()` from `react-router-dom` and needs a Router context to render — its preview (`.design-sync/previews/SetupDoneScreen.tsx`) wraps it in a local `MemoryRouter` rather than using `cfg.provider` globally, since no other component needs a router. It also auto-redirects after a 3s countdown; the capture screenshot happens well before that fires.
- The DS is dark-themed: every real page wraps its content in `<div className="min-h-screen bg-bg-base font-sans">` (see `frontend/src/pages/*.jsx`). Previews rendered on the default white canvas look wrong (ghost/ ghost-danger variants especially — border-only styles need the dark bg to read correctly). Every authored preview in `.design-sync/previews/*.tsx` wraps its story content in a local `Canvas` helper (`<div style={{ background: '#0a0a0b', padding: 24 }}>`) — inline style, not a Tailwind class, since arbitrary/new classes aren't in the compiled CSS (Tailwind only emits utilities actually scanned from `frontend/src`). Keep this pattern for any new/composite previews.
- All 41 components (16 primitives + 25 composites) are authored and graded `good` as of this sync — there is no floor-card backlog to work through on a future re-sync, only genuinely new/changed components.

## Re-sync risks — what to watch on the next sync

- **Stale compiled CSS is the #1 risk.** `cssEntry` points at `frontend/dist/ds-styles.css`, a copy of vite's hashed build output. If a re-sync runs the converter without first re-running `buildCmd` (`npm --prefix frontend run build && cp frontend/dist/assets/index-*.css frontend/dist/ds-styles.css`), it silently reuses whatever `frontend/dist/` last contained — possibly stale or (if `frontend/dist` was deleted) missing entirely (`[CSS_PLACEHOLDER]`/`[NO_DIST]`-style failure). Always rebuild `frontend` first.
- **`componentSrcMap` is a hand-maintained enumeration**, not auto-discovered (no `.d.ts` exists to drive discovery). If a component is added to `frontend/src/design-system/{primitives,composites}/` and exported from `index.js`, it will NOT be picked up until its name+path is added to `cfg.componentSrcMap` — there's no `[ZERO_MATCH]`-style warning for "one new component missing," since the other 41 will still resolve fine.
- **`dtsPropsFor` for the 16 primitives is hand-written and does not auto-update** if a component's actual props change in `frontend/src/design-system/primitives/*.jsx`. A prop rename/addition in source won't be reflected in the shipped `.d.ts` until `dtsPropsFor` is edited to match — there's no type-checker to catch the drift since the source is plain JS.
- **`extraEntries: ["react-router-dom"]` exists solely for `SetupDoneScreen`.** If that component is ever removed or reworked to not need a router, remove the extraEntries too — it's currently paying a ~3x bundle-size tax (172KB → 581KB) for one component's preview.
- **Grades are keyed to config+preview content as a whole**, not per-component — editing `cfg.overrides`/`cfg.extraEntries`/similar global config fields clears grades for components that didn't functionally change (observed firsthand: adding `extraEntries` cleared all 16 primitives' grades even though only `SetupDoneScreen` needed it). This is expected/documented behavior, not a bug — budget a quick re-eyeball of the contact sheets after any global config edit, even when the visual diff is expected to be zero.
- **The Google Fonts substitution (`runtimeFontPrefixes: ["Geist"]`) is a real, unresolved gap** — component previews and any design built with this DS render in a fallback font unless the design agent's own environment happens to load Geist from Google Fonts independently. If pixel-accurate typography ever matters, this needs revisiting (e.g. self-hosting the woff2 files via `extraFonts`).
